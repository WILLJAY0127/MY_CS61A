## 贯穿主线(知识链,逐步把散落的讲次串成一条有因果的线)

```
Lec01&02: 两条线
  Expression 线(求值):primitive(数字/名字)→ call expression(嵌套组合)
  Statement 线(执行):assignment(绑数据值)→ def(绑计算过程)
  汇合点:print(expression 调用产生 statement 的 side effect)
  枢纽:environment(expression 侧查它给含义,statement 侧改它的 binding)
  暗线:function vs data 不那么分明(f=max、def 与 assignment 同构)
        → 终将统一(Lec04 HOF / Lec05 环境 / Lec29-32 interpreter)
```

## 核心洞察(结论式)

- **组合≠抽象**:组合只是拼装,抽象是拼装后加边界隐藏细节。判据:修改内部实现,外部调用代码要不要改。(Lec01&02)
- **叶子≠数字**:叶子节点有两类——数字字面量和名字。函数名也是叶子,它绑的值是函数对象。(Lec01&02)
- **环境根本作用是赋予含义**:环境给标识符赋予含义,隔离只是衍生能力。脱离环境,add(x,1) 毫无意义。(Lec01&02)
- **some of 是阶段小结**:教材 1.3 开篇"some of the elements"表明已列要素不是全集,后续会引入更多。(Lec01&02)
- **Python 是通用通道流派**:Python/JS/Scheme 用同一套语法通道承载数据和函数;C/Java 选隔离通道。这是语言设计主动取舍。(Lec01&02,延伸到 Lec04/29)
- **def 是"小的 global 域"**:函数调用和 global 环境本质同类(都是 frame)。函数内部绑定不该外泄,嵌套调用时同名互相踩,所以每次调用各建独立 frame。"屏蔽"≠"覆盖":inner 帧用完销毁,outer 的绑定从未被动过。(Lec01&02)
- **def 绑计算过程,assignment 绑数据值**:def 抽象的是无数据的计算过程,调用时提供实参配合才执行。这是 def 比 assignment "more powerful" 的实质:绑定粒度不同。(Lec01&02)
