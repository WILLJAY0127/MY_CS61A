# 讲次笔记模板(可复用)

> **用途**:CS61A 每讲课程笔记的标题结构模板。
> **来源**:Lec01&02 验证版,2026-09-07 定稿(迭代过程:去线性堆砌 → 忠于教材两条线 → 中文结论式 → 禁对话体 → 行内区分原话与概括)。
> **关联**:CLAUDE.md「L — Link 链接知识」段;实际写笔记时套这个结构。

## 结构规则

- **每讲必有**:frontmatter、标题 + Core Question、资料清单、主线推导、核心洞察、Java 桥梁、纠错与突破、相关概念、复习卡
- **主线推导段的名称按本讲知识实际走向定**(不硬套):定稿版 Lec01&02 用的是"起点 → Expression 侧 → Statement 侧 → 枢纽 → 汇合点 → 收束";别的讲可能是"数据抽象的动机 → 实现 → 泛化"等。核心要求:**矛盾/局限引出下一段,不是并列摆放**
- **中文为主,核心术语保留英文**(与 CS61A 英文教材对应:call expression / environment / frame / binding / pure / non-pure / side effect / leaf 等)
- **精简**:只放知识结构 + 洞察结论 + 桥梁 + 卡片本身,不放过程叙述

## 硬性规则(沿用 CLAUDE.md)

- **结论式,禁止对话体** — 笔记是易总结论式的东西:不写"原话:""推导:""直觉→修正"、不出现人名、不出现"我/你"式对话残留;洞察直接陈述,来源只标文件路径
- **层间桥梁优先,不堆砌孤立知识点** — 每个概念要回答"为什么会讲到这个"
- **交付为真正的 .md 文件**(headers + fenced code blocks + Obsidian 双链)
- **文件名与 slides 文件名对齐**:`Lec02 - Functions.md` ↔ `02-Functions_1pp.pdf`
- **包含 Java/设计模式桥梁**
- **忠于教材**:先读 PPT + 字幕 + 教材小节正文(不是只读标题),再写笔记——教材正文必读,标题不够;**所有引语用 rg 在教材 html 里逐字核实**,确认存在且位置正确后才标注"原文";概括与原话行内区分(引号内=原话,破折号后=概括),不设"澄清块"式自我审查段落,不把自己造的因果链当教材观点写
- **写完自查清单**:①引语逐条核实过?②编号(R 卡)连续且顺序正确?③三份关联文件同步了(Review_Queue 补新卡、学习导航更新总问题/主线/洞察/术语、模板如需修订)?④通读一遍,删掉所有自我指涉/对话残留?
