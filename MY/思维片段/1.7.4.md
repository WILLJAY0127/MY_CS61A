def fib(n):
    if n == 1:
        return 0
    if n == 2:
        return 1
    else:
        return fib(n‑2) + fib(n‑1)

result = fib(6)

重点：和之前链式递归最大区别：一层函数，同时发起两次独立递归调用，形成树递归。
表达式 fib(n‑2) + fib(n‑1)：
先算左边 fib(n‑2)，本层帧挂起等待左边返回；
左边全部算完回来，再去算右边 fib(n‑1)，本层再次挂起等待右边；
左右都拿到结果，本层做加法，返回。

执行时序（按照解释器真实运行顺序）
fib(6) 被调用，n 不是 1、2，需要计算 fib(4)+fib(5)
先执行左边 fib (4)，fib (6) 帧挂起
fib (4)：算 fib(2)+fib(3)
左边 fib (2) 命中 base case 返回 1
右边 fib (3)：算fib(1)+fib(2)
fib (1) 返回 0；fib (2) 返回 1；相加得到 1
fib(4) = 1 + 1 = 2，返回给 fib (6)
👉现在左边 fib (4) 算完，得到 2；fib (6) 恢复，接下来算右边 fib(5)，再次挂起。
执行 fib(5)：算fib(3)+fib(4)
fib(3) → 1
fib(4) → 2
fib(5) = 1+2 =3 返回给 fib (6)
fib (6) 拿到左右两个结果：2 + 3 =5 返回。
注意现象：大量重复计算！
fib(3)、fib(4)被重复算了好多遍，这是朴素树递归的典型问题。
用「递归信念飞跃」思考（写代码的思路，不要模拟整棵树）
base case：fib(1)=0，fib(2)=1。
信念飞跃：相信 fib(n‑2)、fib(n‑1) 都可以算出正确结果。
直接写：return fib(n‑2)+fib(n‑1)。
写代码的时候不要去脑补整棵爆炸的调用树；只有调试理解执行过程的时候，才去展开。
和前面链式递归对比
链式递归（fact、cascade、互递归石子游戏）：每一层最多只会产生一个子调用，调用链是一条直线。
树递归 fib：一层里面发起两个子调用；父节点要等待多个子任务全部完成，聚合它们的结果，再做加法返回。
这就是上一节结尾预告的：when a single function call makes multiple direct recursive calls，单个函数产生多次直接递归调用。
能不能写成尾递归？
这个朴素写法不能直接转尾递归。
因为本层需要等待两个子调用都返回，再相加；不是把全部计算提前做完往下传。
当然斐波那契本身有迭代版本、也有带累加参数的尾递归版本，但那是换了一套递推逻辑，不是直接改造这个双递归表达式。
能不能用 while 实现？
可以，非常简单，普通迭代，不需要手动栈：
python
运行
def fib_iter(n):
    a, b = 0, 1
    for _ in range(n-2):
        a, b = b, a+b
    return b

这个是自底向上迭代，效率远高于朴素树递归。
补充：如果非要用 while 模拟原版树递归的完整行为，就必须手写栈，模拟这棵树的调用顺序，会相当复杂。朴素树递归天然依赖系统调用栈管理多子任务。
所以感觉像是一个左右的感觉，左边一路向下先搞定玩，在右边
完全正确，Python 的求值顺序就是先左后右。
表达式：fib(n‑2) + fib(n‑1)
先求加号左边：完整跑完 fib(n‑2)，这一整棵子树全部算完、返回出结果；本层函数帧全程挂起不动。
左边全部结束之后，才去求加号右边：完整跑完 fib(n‑1)，把右边整棵子树算完。
左右两边值都到手，本层做加法，返回总和。
拿 fib(6) 再简化时序：
plaintext
fib(6) 要算 fib(4) + fib(5)

第一步：完整把 fib(4) 这一整颗子树从头到尾跑完，得到2。
👉 fib(6) 一直挂在这里等待，不会碰fib(5)。

第二步：fib(4)返回2之后，才开始完整跑 fib(5) 整棵子树，得到3。

第三步：2 + 3 =5 返回。

不是 “左边走一步，右边走一步交替”。
是左边整棵树彻底全部执行完毕，才轮到右边。
再往小一层看 fib(3)：fib(1)+fib(2)
先跑完整 fib(1) →得到 0
再跑完整 fib(2) →得到 1
相加返回 1。
联系栈帧行为
fib(6)帧压栈 → 调用fib(4)，一层层压栈，一路走到 base case，一层层回卷，把左边全部弹完；
回到 fib (6) 这一层，才发起右边fib(5)，又重新一轮压栈、回卷。
和之前链式递归做对比
链式递归：每一层最多 1 个子调用，调用链是一条直线。
fib 树递归：一层里面两个子调用；严格先完整处理左侧全部子树，再处理右侧全部子树。父节点要等多个子任务全部回来之后，聚合结果。
信念飞跃在这里依然生效：写代码的时候不用脑补这一整棵左右来回的调用树；直接相信fib(n‑2)、fib(n‑1)给正确结果。只有理解执行过程、分析性能的时候，才去看这棵树。
这也是朴素 fib 递归爆炸的根源：很多子问题（fib (3),fib (4)）会被左右不同分支反复重新计算。
