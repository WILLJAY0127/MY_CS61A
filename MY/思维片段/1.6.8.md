这段话核心想表达什么（CS61A 1.6 章节小结）
两层递进：普通函数做第一层抽象；高阶函数是抽象之上再做抽象。
第一层：普通自定义函数
普通def函数已经是抽象工具：
把一套计算逻辑包装成函数，函数变成语言里的 “一等元素”，不再只是写死的代码片段。
比如把求平方根迭代逻辑封装成sqrt(a)，你调用时不用关心内部循环细节。
但是：普通函数只能调用它，很难把 “算法模式本身” 拿来加工、组合、改造。
第二层：高阶函数的价值
高阶函数可以把函数当成数据：传入、返回、组合、柯里化、compose 函数组合。
你不再仅仅使用抽象，你可以操作抽象本身，制造出新的抽象。
例子你前面学过的：
improve(update, close)：把迭代算法框架抽出来，迭代模式本身变成代码；
compose1(f,g)：函数组合模式；
嵌套 / 闭包 /lambda：动态生成适配签名的函数。
普通函数：把具体计算打包；
高阶函数：把计算模式、算法模板打包。
后面一大段程序员的忠告（非常重要的工程观点）
要善于识别程序里重复的模式，把它提炼抽象出来；
但不要盲目追求过度抽象，高手会权衡，选择合适抽象层级，不是越抽象越好；
但你必须具备抽象思考能力，遇到新问题时，你能拿这套模式复用；
高阶函数最大意义：让这些抽象模式变成语言里实实在在的值，像数字、字符串一样，可以传来传去、保存、生成。
通俗大白话总结
普通函数：把重复的计算步骤封装。
高阶函数：把重复的算法套路封装。
比如牛顿迭代、迭代求根，这套 “反复更新直到收敛” 的套路，用普通函数每次都要手写循环；
用高阶函数improve，把套路抽出来，不同方程只换小的 update、close 函数即可。
不是为了炫技写晦涩 lambda；而是语言给了你能力，让模式本身成为代码的一部分。同时提醒：不要滥用抽象。
对应你已经看过的代码例子
improve：抽象「迭代收敛」这个模式；
compose1：抽象「函数组合」这个模式；
柯里化：抽象「分步传参」这个模式。
这些模式本身，都变成可以传递、返回的函数对象，这就是本章的落脚点。
操作抽象本身，制造出新的抽象  解释一下
操作抽象本身，制造出新的抽象
先拆两句：
使用抽象：拿已经写好的函数直接调用
操作抽象本身：把函数当作数据，传入、返回、改造、组合旧函数，产出全新的函数（新抽象）
举通俗对比
普通函数：使用抽象
你写了 sqrt(a)，这是一个抽象：你不用关心内部迭代细节，直接调用 sqrt(4)。
👉 你只是使用这个抽象，调用它得到结果。你没有去修改、加工 sqrt 这个函数本身。
高阶函数：操作抽象
你手里有两个旧抽象（旧函数）：
square(x) 求平方
inc(x) 加一
python
运行
compose1 = lambda f,g: lambda x: f(g(x))
h = compose1(square, inc)

compose1 拿到两个已经存在的函数（抽象），不去调用它们求值，而是把这两个函数作为材料加工，生成一个全新的函数 h。
square、inc：旧抽象
compose1 操作这两个旧抽象
产出 h(x) = square(inc(x))：全新的抽象，之前代码里根本不存在
这就叫：操作抽象本身，制造出新的抽象。
不是拿抽象跑一遍得到数字结果；而是拿抽象当原料，组装出新的抽象（新函数）。
再用 improve 的例子理解
improve(update, close)
update、close 是两个现成小函数（两套小抽象）
improve 是高阶函数，接收这两个抽象，内部执行迭代逻辑，返回最终数值。
而 sqrt 内部用嵌套 /lambda，又把多参的数学逻辑，加工成适配 improve 的单参 update，动态制造出新的 update 函数。
原来的数学更新式是 sqrt_update(x,a) 两个参数，不能直接给 improve。
通过嵌套闭包，捕获 a，造出全新单参函数：wrapper(x)。
旧抽象：双参数更新函数；经过操作，生成新抽象：单参 wrapper。
区分两个完全不同的行为（极易混淆）
调用抽象（普通使用）
python
运行
res = square(3)
# 使用抽象square，得到数字结果10，产物是数据，不是新抽象

操作抽象（高阶函数做的事）
python
运行
h = compose1(square, inc)
# 不执行square、inc；把两个函数对象拿来组合
# 产物 h 是**新函数（新抽象）**，不是数字

调用：输入函数 + 数据 → 产出数据
操作抽象：输入函数 + 函数 → 产出新函数（新抽象）
联系教材那句话
higher‑order functions permit us to manipulate these general methods to create further abstractions
manipulate these general methods = manipulate abstractions：操作这些通用方法（也就是操作函数抽象）
create further abstractions：制造更多、新的抽象。
大白话总结
普通代码：拿函数算结果。
高阶函数：拿函数当积木，拼出新函数。积木是旧抽象，拼出来的成品就是新抽象。
注意：抽象不一定越复杂越好，教材后面也提醒，不要无脑堆砌抽象，要匹配业务场景。能力给你，但要克制使用。
