以前我们学的不可变值（数字 4、字符串）不存在这个麻烦；
但带状态的闭包函数是会变的 “可变对象”，如果多个名字指向同一个闭包函数，改一个，另一个跟着变。

纯不可变数据（比如数字 4）

带内部状态的闭包函数（可变实体）
这种东西自身内部藏着会变化的状态（f1 里的 balance）

这就是非局部赋值带来的复杂度代价：相等不再只是 “值相等”，还要关心是不是同一个实体
原文那句核心解题口诀（做环境图必考）
只有调用函数，才会创建新帧；赋值只会修改已有帧里的绑定。
make_withdraw() 这种函数调用 → 新帧、新独立状态
wd2 = wd 单纯名字赋值 → 不会新建任何帧！共用原有状态

一、整段核心一句话概括
引入可变、非纯函数之后，引用透明性失效；我们要区分两件事：「两个对象内容相等」和「两个对象是同一个实体（拥有同一性 identity）」。
可变状态带来了这套复杂度，但同时它也让我们能自己实现可变抽象数据类型（类似 list /dict）。
关键词清单：引用透明 referentially transparent、同一性 identity、纯函数 / 非纯函数
二、逐段拆解翻译 + 通俗解释
第一段
Sameness and change. These subtleties arise because, by introducing non-pure functions that change the non-local environment, we have changed the nature of expressions. An expression that contains only pure function calls is referentially transparent; its value does not change if we substitute one of its subexpression with the value of that subexpression.
相同与变化。这些复杂问题之所以出现，根源是我们引入了能修改外部环境的非纯函数，表达式的性质就此改变。只由纯函数构成的表达式具备引用透明性：你可以把子表达式直接替换成它算出的值，整个表达式最终结果不变。
✅ 引用透明（重点概念）
纯函数例子（引用透明）：
python
运行
def add(a,b):
    return a+b
add(2,3) + add(1,4)
add(2,3) 永远等于 5，直接替换成 5 + 5，结果完全不变。
❌ 非纯函数（不再引用透明）
wd(1) 这个取款函数，每次调用结果取决于历史状态，同样的wd(1)，不同时刻返回值不一样，不能直接固定替换成某个数字。
第二段
Re-binding operations violate the conditions of referential transparency because they do more than return a value; they change the environment. When we introduce arbitrary re-binding, we encounter a thorny epistemological issue: what it means for two values to be the same. In our environment model of computation, two separately defined functions are not the same, because changes to one may not be reflected in the other.
重新绑定会破坏引用透明，因为它不止返回结果，还修改了环境。一旦允许重新绑定，就冒出一个很难的根本问题：两个 “值相等” 到底是什么意思？在环境模型里，两次独立创建出来的带状态函数并不是同一个东西，修改其中一个，不会影响另一个。
纯世界里：值相等就是完全等价，可以互换；
可变世界里：要区分：值相等 ≠ 是同一个实体
wd = make_withdraw(12) 和 wd2 = make_withdraw(12)
二者此刻余额一样，但不是同一个账户，互不影响。
第三段（非常核心，SICP/Composing Programs 经典观点）
In general, so long as we never modify data objects, we can regard a compound data object to be precisely the totality of its pieces. For example, a rational number is determined by giving its numerator and its denominator. But this view is no longer valid in the presence of change, where a compound data object has an "identity" that is something different from the pieces of which it is composed. A bank account is still "the same" bank account even if we change the balance by making a withdrawal; conversely, we could have two bank accounts that happen to have the same balance, but are different objects.
只要数据永远不可修改，复合对象就完全等价于它的所有组成部分。比如一个有理数，只要分子分母确定，这个有理数就唯一确定。
但一旦允许修改，这套看法就失效了：复合对象拥有【同一性（identity）】，这种身份独立于它当下的内容。
哪怕取了钱、余额变了，这个银行账户依然是同一个账户；反过来，两个账户余额碰巧一样，但它们是完全独立的两个不同对象。
举直白例子：
不可变：分数 12/1，只要分子分母是 12、1，它就是同一个东西
可变账户：账户 A 余额 12 → 取钱变成 11，账户 A 本身还是那个账户（身份不变）；同时可以存在账户 B 余额也是 11，但 B 是另一个独立账户
这就是编程里 equality（值相等） vs identity（同一实体） 的经典区分
第四段
Despite the complications it introduces, non-local assignment is a powerful tool for creating modular programs. Different parts of a program, which correspond to different environment frames, can evolve separately throughout program execution. Moreover, using functions with local state, we are able to implement mutable data types. In fact, we can implement abstract data types that are equivalent to the built-in list and dict types introduced above.
尽管带来了复杂度，但非局部赋值是构建模块化程序的强大工具。程序里不同部分对应独立的环境帧，可以各自独立演化。
另外，依靠带局部状态的函数，我们完全可以自己实现可变数据类型。实际上，我们能实现和内置 list、dict 等价的抽象数据类型。
👉 一句话：代价是破坏引用透明、要区分同一性；收益是可以从零实现可变 ADT（抽象数据类型），不用依赖语言自带的列表字典。
这也是函数式风格模拟面向对象 / 可变容器的核心思路。

① 重新绑定会修改环境，破坏引用透明
重新绑定（re-binding）：nonlocal balance; balance = balance - amt
不是修改balance这个变量名本身，而是在外层环境帧里面，修改balance这个名字对应的绑定值。
👉 这件动作改动了环境帧（环境变了）。
引用透明：同一个表达式，每次执行结果必须一模一样，可以直接替换成返回值。
现在：
python
运行
wd = make_withdraw(100)
wd(10) # 返回90
wd(10) # 返回80

完全相同表达式wd(10)，两次结果不一样。
原因：第一次执行发生了重新绑定，环境被改了。
✅ 结论：重新绑定 → 环境变化 → 引用透明不再成立。
② 一旦状态可变，仅仅比较内容无法判断两个实体是否是同一个
不可变场景：只看内容就行。a=4, b=4，内容相同，完全不用关心是不是同一个对象。
可变场景：
python
运行
wd1 = make_withdraw(100)
wd2 = make_withdraw(100)

此时此刻，wd1、wd2 对应的余额内容都是 100。
但它们根本不是同一个账户实体。
之后wd1(10)，wd1 余额变成 90，wd2 依旧 100。
👉 只看当下内容，区分不开是不是同一个实体，必须判断身份（is）。
③ 两次独立调用 make_withdraw 生成的闭包函数，是两个不同对象，状态互相隔离
python
运行
wd1 = make_withdraw(100) # 第一次调用
wd2 = make_withdraw(100) # 第二次独立调用

规则：每一次调用函数，都会新建一个环境帧
第一次调用 → 新建帧 F1，F1 里有balance=100，wd1 绑定到这个帧内的 withdraw 函数
第二次调用 → 新建帧 F2，F2 里有balance=100，wd2 绑定到这个帧内的 withdraw 函数
F1、F2 互相独立。修改 F1 里的 balance，不会影响 F2 里的 balance。
所以 wd1 和 wd2 是两个独立对象，状态隔离。
极简一句话汇总这整句
变量的重新绑定会改动环境，导致同一个表达式多次运行结果不一样（引用透明失效）；存在可变状态时，光看当前值不能判断是不是同一个东西；每调用一次make_withdraw就新建一套独立环境，两次调用得到两个互不干扰的闭包。
