核心一句话
前面版本用一堆if/elif做消息分发；调度字典（dispatch dictionary）改用字典查表替代 if 分支，把消息名字（字符串）直接映射到对应的处理函数。
同时这个字典里既存状态（balance 余额），又存方法（deposit/withdraw 函数），靠字典的可变特性，直接修改字典内的值，省去 nonlocal。
1. 和上一节消息传递的对比
旧方案（if/elif dispatch）
python
运行
def dispatch(message, value=None):
    if message == 'deposit':
        ...
    elif message == 'withdraw':
        ...

新增消息，必须手动增加elif分支
状态放在外层帧变量，修改需要nonlocal
新方案：调度字典
python
运行f
dispatch = {
    'deposit': deposit,
    'withdraw': withdraw,
    'balance': initial_balance
}

消息就是字典 key，查表直接拿到函数，不再写长长的 if 串
状态balance直接放在这个 dict 里面
2. 重点：为什么这里不用 nonlocal？
python
运行
def deposit(amount):
    dispatch['balance'] += amount
    return dispatch['balance']

拆解：
dispatch是外层 account 帧里的字典变量。
dispatch['balance'] += amount
👉 不是对名字 dispatch 重新绑定，是原地修改字典对象内部的元素
没有写 dispatch = xxx（这是 rebinding，才需要 nonlocal）
只是修改字典这个可变对象里面'balance'对应的值
所以内层deposit/withdraw不需要nonlocal。
关键区分（极易混淆）
dispatch['balance'] += 5：原地修改 dict 内部元素 ✅ 不用 nonlocal
dispatch = {...}：给名字 dispatch 绑定新对象 ❌ 需要 nonlocal
3. 这个 account 结构长什么样
调用 a = account(20)
返回的a就是这个字典：
python
运行
{
    'deposit': deposit函数,
    'withdraw': withdraw函数,
    'balance': 20
}

字典里面混合存放数据（数值）和行为（函数）。
然后配套三个外部选择器函数，用来操作这个账户：
python
运行
def withdraw(account, amount):
    return account['withdraw'](amount) # 取出字典里的withdraw函数调用
def deposit(account, amount):
    return account['deposit'](amount)
def check_balance(account):
    return account['balance']

使用：
python
运行
a = account(20)
deposit(a,5)      # a['balance'] 变成25
withdraw(a,17)    # a['balance'] 变成8
check_balance(a)  # 返回8

4. += 的说明
python
运行
a += 1
# 等价于
a = a + 1

教材这里顺带提一句：+=是查找 + 重新赋值简写。
放到 dispatch['balance'] += amount：先取出dispatch['balance']的值，加上 amount，再写回字典里面'balance'这个位置。
5. 教材讲调度字典的目的
优化消息分发：字典查表替代 if/elif，代码更干净，新增消息只需要往字典里加 key，不用写条件分支
演示另一种封装思路：状态和方法打包放进同一个可变字典
展示两种实现可变状态的方式对比：
方式 A：闭包外层变量 + nonlocal（前面 mutable_link、dictionary、make_withdraw）
方式 B：可变容器（dict）保存状态，原地修改容器内元素，无需 nonlocal（本节 account）
一句话浓缩本段
调度字典用字典代替 if 条件分支做消息查找；把状态和函数全部放进同一个字典对象，利用字典原地修改特性，不再需要 nonlocal 声明，这是消息传递范式的另一种实现形式。

一句话核心意义
CS61A 在这里是横向展示：实现「带状态的对象」不止一条路。
前面：闭包 + nonlocal（修改外层变量绑定）
本节：可变容器（dict/list）存放状态 + 函数，原地修改容器内部，绕开 nonlocal
本质目的：对比两种不同的状态管理模型，理解绑定（binding） 和可变对象（mutable value） 的根本区别。
先回答你这句：可变容器在外层帧共享，不受 nonlocal 束缚
python
运行
def account(initial_balance):
    def deposit(amount):
        dispatch['balance'] += amount  # 重点！
    dispatch = {'balance': initial_balance, 'deposit': deposit}
    return dispatch

外层帧：名字 dispatch 绑定到字典对象（字典本身是独立可变容器）
内层 deposit 函数只读名字dispatch，没有写 dispatch = xxx（没有重新绑定这个名字）
操作只是：修改字典里面的元素，不是修改「dispatch这个名字指向谁」
👉 所以不需要nonlocal。
nonlocal 管的是：对变量名重新绑定；
nonlocal 不管：原地修改一个可变容器里面的内容。
两种状态方案的本质差异（课程最想让你看懂的）
方案 1（前面 mutable_link、make_withdraw）
状态：简单变量 contents / balance
修改方式：contents = link(...) → 重新绑定名字 → 必须 nonlocal
方案 2（本节 dispatch 字典）
状态：打包进可变容器 dict
修改方式：dispatch['balance'] += x → 原地修改容器内部的值，名字 dispatch 本身指向的对象不变 → 不需要 nonlocal
你提到的：list 里面也可以放方法，为什么单独拿 dict 来讲调度字典？
list 当然也能存函数（放方法），但是list 靠下标索引，不适合消息分发。
消息传递需要：消息字符串 → 找到对应函数。
dict：key 是字符串"deposit"、"withdraw"，直接查表，天然匹配消息传递，可读性极强。
list：只能用 0、1、2 数字下标，你没法用名字去检索对应的操作函数，不适合消息分发。
举例子对比：
python
运行
# dict（调度字典，本节方案）
dispatch["deposit"](5)

# 如果强行用list存方法
dispatch[0](5) # 0代表deposit，人很难看懂，新增方法很难维护

所以：list 可以存放函数，但不适合做「消息调度」；字典天生适合做消息分发表。
教材介绍这套方案的 3 层教学目的（由浅到深）
语法层面：分清两件完全不一样的事情
给名字重新绑定（x = ...，需要 nonlocal）
修改可变容器内部元素（dict[key] += ...，不需要 nonlocal）
这是 Python 作用域里最容易踩坑的点，课程在这里专门拆开演示。
架构层面：消息传递的两种实现
版本 1：if/elif 条件分发（上一节 mutable_link）
版本 2：调度字典查表分发（本节 account）
证明：消息传递是独立思想，底层实现可以换。新增消息，只需要往字典追加 key，不用写一堆 elif。
拔高（铺垫面向对象）
把数据 + 操作数据的函数打包在同一个容器内，这就是 Python class 底层思想原型：
a['balance'] 就是实例属性
a['deposit'] 就是实例方法
后面学到类的时候你会发现：obj.deposit() 本质就是从对象字典里取出 deposit 函数执行。
