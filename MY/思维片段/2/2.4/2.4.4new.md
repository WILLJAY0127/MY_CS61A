Lists and dictionaries have local state: they are changing values that have some particular contents at any point in the execution of a program. The word "state" implies an evolving process in which that state may change.
列表和字典拥有局部状态：它们是可变的值，在程序执行的任意时刻都持有特定内容。“状态” 这个词代表着一个持续变化的过程，状态本身可以被修改。
Functions can also have local state. For instance, let us define a function that models the process of withdrawing money from a bank account. If there is enough money in the account to accommodate the withdrawal, then withdraw will return the balance remaining after the withdrawal. Otherwise, withdraw will return the message 'Insufficient funds'. 函数同样可以拥有局部状态。举个例子，我们定义一个函数来模拟从银行账户取钱的过程。创建名为 withdraw 的函数，参数是本次取款金额。如果账户余额足够支付本次取款，withdraw 返回取款之后剩余余额；否则返回字符串 'Insufficient funds'（余额不足）。举个例子：账户初始有 100 美元，我们连续调用 withdraw，希望得到下面这一组返回结果：
这个例子的核心概念：带状态的函数 / 闭包保存状态
普通函数：每次调用只依赖输入参数，两次独立调用互不影响，没有记忆。
带状态函数（闭包）：函数会记住上一次调用后的余额，每次调用会修改这个保存下来的状态。

重点：函数 withdraw 本身记住余额，余额是保存在闭包环境里的局部状态，不是全局变量。
CS61A 标准实现代码（Composing Programs 原版）
python
运行
def make_withdraw(balance):
    def withdraw(amount):
        nonlocal balance   # 声明balance不是当前内层函数局部变量，去外层找
        if amount > balance:
            return 'Insufficient funds'
        balance = balance - amount
        return balance
    return withdraw

wd = make_withdraw(100)
wd(25)  # 75
wd(25)  # 50
wd(60)  # 'Insufficient funds'
wd(15)  # 35
关键点拆解（考试高频）
make_withdraw(100) 创建一个环境帧，里面绑定变量 balance = 100
返回内层函数 withdraw，这个函数携带外层的环境（闭包）
nonlocal balance：告诉 Python：balance 在外层环境，允许在内层修改外层绑定的值
每次调用 wd(amount)，都会读取、修改这个保存在闭包中的 balance（也就是函数的局部状态）
你可以创建多个独立账户，互不干扰：
python
运行
wd1 = make_withdraw(100)

# wd1 和 wd2 各自有独立的 balance 状态，互不影响

列表、字典自带可变状态；而借助闭包 + nonlocal，函数也可以拥有属于自己、跨调用持续保留、可以修改的局部状态。

逐句精读 + CS61A 核心解读
By introducing nonlocal statements, we have created a dual role for assignment statements. Either they change local bindings, or they change nonlocal bindings.
通过引入nonlocal语句，赋值语句就有了两种作用：修改局部绑定，或者修改非局部绑定。
In fact, assignment statements already had a dual role: they either created new bindings or re-bound existing names.
其实赋值语句本身本来就具备双重作用：新建绑定，或是对已经存在的名字重新绑定。
Assignment can also change the contents of lists and dictionaries.
赋值还可以修改列表、字典这类可变对象内部的内容（原地修改）。
The many roles of Python assignment can obscure the effects of executing an assignment statement.
Python 的赋值拥有这么多不同效果，很容易让人看不清一条赋值语句到底会发生什么。
It is up to you as a programmer to document your code clearly so that the effects of assignment can be understood by others.
作为程序员，你需要写清晰注释 / 文档，让别人看懂这条赋值到底会产生什么影响。
拆解三层不同的赋值行为（本段最重要，考试区分点）
① 名字绑定层面（= 绑定名字，分两种）
局部绑定 local
python
运行
def f():
    x = 10  # 在当前函数本地帧，新建名字x的绑定
nonlocal 绑定
python
运行
def f():
    x = 10
    def g():
        nonlocal x
        x = 20 # 不是新建，修改外层已经存在的x绑定
这就是第一句说的：赋值要么改 local，要么改 nonlocal 绑定。
同时，名字绑定本身又分：
不存在这个名字 → 创建新绑定
名字已经存在 → 重新绑定（把名字指向另一个对象）
python
运行
x = 1
x = 2 # 重新绑定：名字x不再指向1，改为指向2
② 可变对象内部修改（另一种完全不同的效果！）
python
运行
lst = [1,2]
lst[0] = 99
这里 lst[0] = 99，并没有修改名字 lst 的绑定：lst 仍然指向原来那个列表对象。
只是原地修改列表对象里面的内容。
字典同理：d['a'] = 10。
✅ 重点区分两个概念（CS61A 极易混淆）
名字重绑定：name = 新对象，名字指向别的对象；
可变对象原地修改：name[index] = val，名字不变，修改对象内部数据。
一句话总结本段主旨
Python 里=赋值有好几种完全不一样的效果：
在本地新建 / 重绑定名字
通过nonlocal修改外层函数帧的名字绑定
通过lst[i] / d[k]原地修改可变对象内部内容
多种行为混在一起，可读性会变差，所以写代码要做好注释，明确赋值带来的状态变化。


中英对照 + CS61A 核心解读
Python Particulars. This pattern of non-local assignment is a general feature of programming languages with higher-order functions and lexical scope. Most other languages do not require a nonlocal statement at all. Instead, non-local assignment is often the default behavior of assignment statements.
Python 的特殊细节。这种非局部赋值模式，是带有高阶函数、词法作用域的编程语言的通用特性。但绝大多数其他语言根本不需要 nonlocal 关键字；在那些语言里，对非局部变量赋值通常就是赋值语句的默认行为。
Python also has an unusual restriction regarding the lookup of names: within the body of a function, all instances of a name must refer to the same frame.
Python 在名字查找上还有一条独特限制：在同一个函数体内，同一个名字的所有出现，必须全部指向同一个帧。
As a result, Python cannot look up the value of a name in a non-local frame, then bind that same name in the local frame, because the same name would be accessed in two different frames in the same function.
由此带来一个结果：Python 不允许「先去非局部帧读取这个名字，又在本局部帧给同一个名字赋值」。因为这样同一个名字，在同一个函数里面，同时关联两个不同的帧，这是 Python 禁止的。
This restriction allows Python to pre-compute which frame contains each name before executing the body of a function.
这个限制的好处：Python 在运行函数体之前（静态编译阶段），就能预先判定每个名字属于哪一个帧，提前做好静态分析。
When this restriction is violated, a confusing error message results. To demonstrate, the make_withdraw example is repeated below with the nonlocal statement removed.
一旦违反这条限制，就会抛出容易让人困惑的报错。我们把 make_withdraw 去掉 nonlocal，用来演示这个问题。
核心拆解（本段是 CS61A 非常关键的 Python 静态作用域规则）
1. 别的语言（JS / Scheme）对比
JavaScript / Scheme 这类同样拥有高阶函数 + 词法作用域的语言：
在内层函数，直接写 x = x - 1，默认就会向外层查找并修改外层的 x，不需要额外关键字。
Python 选择不一样的设计：赋值默认在本地新建绑定，想修改外层必须写nonlocal。
2. Python 静态规则（重点：同一个函数内，同名变量只能归属唯一帧）
Python 在解析函数代码的时候（还没运行），只要看到函数内部出现 balance = ...（赋值），Python 就直接判定：
balance 是本函数局部变量，整个函数里面所有出现的 balance，全部都属于当前局部帧。
所以下面这段代码：
python
运行
def make_withdraw(balance):
    def withdraw(amount):
        # nonlocal balance 删掉了
        if amount > balance:  # 读取balance → Python认为balance是本函数局部变量
            return 'Insufficient funds'
        balance = balance - amount # 赋值balance → 标记balance为局部变量
        return balance
    return withdraw

wd = make_withdraw(100)
wd(5)
运行报错：UnboundLocalError: local variable 'balance' referenced before assignment
错误根源：
静态扫描时，发现函数内有 balance = ...，于是整个 withdraw 函数内所有 balance 全部标记成局部变量。
执行 if amount > balance 的时候，想去读取本层局部 balance，但是还没有赋值，变量未绑定，直接报错。
原文那句话：
within the body of a function, all instances of a name must refer to the same frame
在一个函数里面，同一个名字，不能一部分引用外层帧，一部分引用本地帧，必须统一归属单一帧。
3. 这个规则的好处
Python 不需要等到运行时再去动态查找变量属于哪一层；在解析阶段一次性确定每个名字所在帧，提升执行效率。
代价就是会出现这个看上去很迷惑的 UnboundLocalError。
一句话浓缩笔记
Python 的特殊规则：单个函数内同一个名字只能属于同一个帧。只要函数内出现对名字的赋值，这个名字就被静态标记成本地变量，整个函数内该名字全部看作局部变量；如果此时你想读取它，而还没有赋值，直接报错。很多带词法作用域 + 高阶函数的语言没有这个限制，也不需要 nonlocal 关键字。
