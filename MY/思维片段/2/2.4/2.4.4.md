前面 2.4.1~2.4.3：数据容器自带状态（list、dict 这种数据本身可以变）

主线依然全书核心：抽象 + 组合
之前状态是放在列表、字典这种 “数据盒子” 里；
这一节：状态可以藏在闭包的环境帧里，附着在函数上，造出 “自带记忆的函数”
不是讲集合 / 方法，是状态这个概念的延伸：状态不止属于数据，函数也可以拥有状态。
✅ 二、全文浓缩总结（逐段提炼核心知识点）
1. 核心概念：局部状态、非纯函数、副作用
list /dict 自带状态：它们的内容可以随程序运行改变
函数也可以拥有局部状态：同一个函数，相同入参，多次调用返回结果不一样 → 非纯函数
纯函数：输入决定输出，无记忆、无副作用（前面学的大多是这种）
非纯函数：内部记住历史信息，调用会产生副作用（修改环境里的变量绑定）
例子：make_withdraw 高阶工厂函数，输入初始余额，产出一个独立的取款函数 withdraw，每次取钱会扣余额、记住剩余金额
2. nonlocal 的核心规则（本节重中之重、考试高频）
内层函数读取外层变量：不需要 nonlocal
内层函数修改外层名字的绑定：必须写 nonlocal 变量名
nonlocal balance 含义：不要在当前 withdraw 本地帧新建 balance，去外层已经定义 balance 的最近一层帧（make_withdraw 的帧 f1）修改这个名字的绑定
底层关键：
每次调用 wd(5) / wd(3) 都会新建临时 withdraw 局部帧（用完就销毁）
但是所有调用共享同一个父帧 f1，balance 就保存在 f1 里面，这就是记忆的来源
3. Python 特殊限制（UnboundLocalError 的根源）
Python 静态预处理规则：同一个函数内，同一个名字的所有引用，必须全部属于同一个帧
只要函数体里出现 balance = xxx 赋值语句，Python 在执行代码之前就判定：balance 是局部变量。
那么前面 if amount > balance: 去读取 balance 时，本地还没赋值 → 直接报错 UnboundLocalError
别的很多语言（JS、Scheme 等）没有这个限制，不需要类似 nonlocal 关键字，这是 Python 独有的特性。
4. 赋值=在 Python 里有多种完全不同效果（本节收尾重点）
本地赋值：x=1 → 在当前帧新建 / 重绑定本地名字
nonlocal 赋值：修改中间外层帧的名字绑定
global 赋值：修改全局帧名字绑定
可变容器修改：lst[0]=1 / d["k"]=1 → 不改动名字绑定，只修改容器内部内容（之前我们不用 nonlocal 实现账户的方案就是这个原理）
坑点：同样一个=符号，底层行为完全不一样，代码可读性容易变差，需要人为写注释维护抽象清晰
5. 补充历史细节
nonlocal 是 Python3 新增，Python2 没有这个关键字。
✅ 三、完整 2.4 整条大脉络串起来（解决你的困惑：节奏跳转逻辑）
2.4 大主题：序列、映射、可变与状态
2.4.1 Sequence Abstraction：序列抽象（有序数据统一接口，len、[]）
2.4.2 Sequence Objects：list 可变、tuple 不可变 → 数据容器可以有状态，引入别名、共享副作用
2.4.3 Dictionaries：映射抽象（key-value 容器，也是可变容器，自带状态）
✅2.4.4 Local State：状态不一定依附在 list/dict 数据上，可以藏在闭包环境，附着在函数上
用高阶函数 + nonlocal 封装私有状态
好处：状态隔离（多个独立账户互不干扰），不用全局变量，维持抽象屏障
代价：变成非纯函数，有副作用，代码推理变难

SICP/Composing Programs 这条路线：不用 class，只用高阶函数 + 闭包就能模拟对象和私有状态
✅ 四、极简速记版（适合你之后复习默写）
状态不只有 list/dict 能存，函数闭包也可以保存私有局部状态，造出非纯函数。
读外层变量不用 nonlocal；修改外层名字绑定必须 nonlocal。
Python 预处理规则：函数内只要出现对名字的赋值，就默认它是局部变量，提前校验，容易报 UnboundLocalError。
多次调用闭包生成的函数：每次新建临时局部帧，但共享同一个外层父帧的状态。
Python 的=有多种行为，容易混淆，是可变代码复杂度的根源。
