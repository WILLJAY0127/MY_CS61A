核心一句话
2.4.3 Dictionaries 是继续扩充「序列之外的另一种核心数据抽象」，并且它本身也是可变对象，承接上一小节 2.4.2 刚讲完的【可变、别名、共享】这套认知。
前面 2.4 讲的序列（list/tuple）是整数下标索引；字典抽象解决：用任意不可变的 key 来做映射查询。
全书主线依然是：抽象 + 组合
1. 它填补了什么抽象缺口？
list /tuple 这种序列，查找元素依靠连续整数索引 0,1,2,3…
适合有序、排成一排的数据：扑克牌列表、一串字符。
但大量现实关系不是顺序编号，是「名字→对应值」的映射：
罗马字符 I→1，V→5
学生学号→成绩
单词→释义
物品名称→库存数量
👉 字典就是专门做「映射（mapping）」的抽象
它对外屏蔽底层怎么存、怎么查找，只给你接口：d[key] 存 / 取。
这就是本节第一句说的：
provide an abstraction for storing and retrieving values that are indexed not by consecutive integers, but by descriptive keys.
2. 和上一小节 2.4.2 的强承接关系（非常关键）
字典本身是可变对象！
python
运行
numerals = {'I':1, 'V':5}
numerals['L'] = 50  # 原地修改字典，不生成新dict对象
所以上一节学的全部知识直接复用：
多个变量别名指向同一个字典 → 一处修改，全部同步看到
可变对象带来副作用、共享问题（和 list 完全一样）
同时新增一条新约束考点：
dict 的 key 必须是不可变类型（不能是 list 这类可变对象）
为什么？抽象 + 底层哈希的要求：key 必须稳定不变，才能定位存储位置。
这里刚好巩固区分：可变 / 不可变对象的适用边界
3. 两个核心规则，是字典这个抽象本身自带的设计约定
同一个 key 最多只能对应 1 个 value（重复赋值直接覆盖）
这是映射这个概念本身的定义：一个输入只能对应一个输出；如果一键多值，就不是简单映射抽象了，需要用列表等别的结构。
旧版 Python 字典无序（课本这个版本强调无序）
也就是你不能依赖 key 的排列顺序，这也是字典抽象和序列抽象重要区别：序列关心顺序，基础字典不关心。
4. 配套工具：get、keys/values/items、字典推导式
get：抽象层面的安全查询，避免 key 不存在直接报错，是日常组合代码很常用的接口
keys()/values()/items()：可迭代接口，让字典可以和循环、求和等已有代码组合（和序列的组合范式统一）
字典推导式：和列表推导式对应，直接生成全新字典（不会复用旧对象，和 list 推导式设计思想一致）
