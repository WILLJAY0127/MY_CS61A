核心提炼：数据的特性（Properties of Data）
1. 核心思想：抽象数据不靠底层存储，靠行为契约（行为条件）判断
什么才算合法的抽象数据（有理数 / 序对 pair）：
不是看底层是不是列表、元组，
而是看：构造器 + 选择器 是否满足约定的行为规则。
✅ 有理数契约：
如果 x = rational(n,d)，那么 numer(x)/denom(x) == n/d
只要这条规则成立，底层用列表、闭包都可以，都是合法实现。
✅ 序对 pair 契约：
如果 p = pair(x,y)，那么 select(p,0)=x，select(p,1)=y
只要满足这条，就是合格的序对。
关键点：行为不变，抽象就有效；上层业务代码不用修改。抽象屏障保护上层不受底层改动影响。
2. 重磅例子：序对可以不用列表，只用函数（闭包）实现
python
运行
def pair(x, y):
    def get(index):
        if index == 0:
            return x
        elif index == 1:
            return y
    return get   # 返回内层函数（闭包，绑定了x,y）

def select(p, i):
    return p(i)
pair(20,14) 返回一个函数（闭包），保存了 x=20,y=14
select(p,0) 等价调用 p(0)，取出 20
👉 颠覆直觉：函数本身就可以用来实现复合数据！
我们平时理解的数据是 “存值的容器”，但在这套理论里：
只要构造 / 选择接口满足行为约定，函数也能充当复合数据。
3. 教材这段话想说明两件事
数据的本质是一组行为约定，不是特定存储结构
不要把 “序对” 等同于二元列表；列表只是其中一种实现方案。
数据抽象的强大之处：自由切换底层实现
序对可以：二元列表 / 闭包函数 两种实现互换；
只要遵守契约，上层调用 select 的代码完全不用改动。
4. 补充区分（容易疑惑）
Python 真实底层不会用闭包实现列表，因为性能差；
教材演示闭包实现序对，只是证明理论可行性：
复合数据不一定需要原生容器，高阶函数（闭包）足够实现。
5. 一句话总结
判断抽象数据是否合法，看构造器与选择器是否满足行为契约，不关心底层怎么存；函数（闭包）完全可以用来实现复合数据。
串联整章逻辑回顾（2.2 全小节）
复合数据：把多个值打包在一起
数据抽象：隔离【数据怎么用】和【数据怎么存】
抽象屏障：分层规范，禁止跨层访问底层细节
数据的特性：数据由行为契约定义，不限定底层实现，函数也能充当复合数据
