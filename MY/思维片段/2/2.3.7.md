这东西和 list 有啥关系啊 没看出来关系啊
一句话核心
底层实现上：我们借用了 Python 原生 list（二元列表 [a,b]）来实现「序对」，再用序对嵌套造出教材定义的链表（linked list）。
抽象概念上：教材链表是【自己重新实现的序列】，和 Python 原生 list 是两套完全独立的序列。
重点区分两个东西，名字都叫 list，非常容易混：
Python 内置 list：[1,2,3,4]，数组式序列（原生）
本节 linked list（链表）：[1, [2, [3, [4, 'empty']]]]，用嵌套二元小 list 拼出来的自定义序列
1. 底层：为什么要用到 [a,b] 这个原生 list？
前面章节铺垫了：序对 (pair) 是最基础的复合数据，序对只存两个东西：first 和 rest。
现在我们最简单的实现方式，直接拿 Python 的双元素 list 充当序对：
[first, rest] 就是一个序对。
python
运行
# link 函数返回的本质就是一个二元list
def link(first, rest):
    return [first, rest]

于是：
python
运行
four = link(1, link(2, link(3, link(4, empty))))
# 展开后就是层层嵌套的二元list
four = [1, [2, [3, [4, 'empty']]]]

👉 没有 Python 原生 list，我们就没有这个 “序对” 的载体。这是唯一的联系！
2. 但是！逻辑语义完全不是一回事
✅ Python 原生 list：[1,2,3,4]
结构：一块连续空间，里面直接放 4 个元素
特点：支持随机索引 lst[2]、内置len()，O(1)
结构不是递归的
✅ 教材自定义链表 linked list：[1, [2, [3, [4, 'empty']]]]
结构：一层一层二元序对嵌套
含义：1 是第一个元素，剩下所有元素是另一个链表[2, [3, [4, 'empty']]]
特点：没有随机访问，取第 N 个必须一步步rest向后遍历，O (n)
结构是递归定义的
举个直观对比
原生 list：[1,2,3,4] 👉 扁平、一层
本节链表：[1, [2, [3, [4, 'empty'] ] ] ] 👉 层层包裹
3. 抽象屏障的思想（CS61A 核心！）
理论上：序对不一定非要用 list 实现！
之前 2.2.4 讲过，序对甚至可以只用纯函数实现，完全不用列表。
python
运行
# 纯函数实现序对，不需要任何list
def make_pair(x, y):
    def dispatch(m):
        if m == 0:
            return x
        else:
            return y
    return dispatch

如果换成函数版本的序对，整个链表逻辑（link/first/rest/len_link）完全不用改，只是底层载体从[a,b]换成了函数。
👉 所以：list 只是临时的底层载体，不是链表本身！
链表是一套数据抽象（构造器 + 选择器 + 规则），list 只是我们拿来落地这个抽象的工具而已。
4. 最容易踩坑的误区
❌ 误区：[1, [2, [3, 'empty']]] 就是普通 list
✅ 纠正：它语法上是 list 嵌套，但我们给它强加了一套额外的规则（is_link 校验、只能用 first/rest 访问），把它解释成了链表结构。
就像：我们用积木（原生 list）搭了一个 “小车（链表抽象）”，积木本身 ≠ 小车。
5. 总结极简版
关系：用二元原生 list 充当序对，嵌套实现自定义链表
区别：
原生 list：扁平数组，内置全套高效能力
linked list：递归嵌套的自定义序列，只能顺序遍历，效率低
课程目的：不是教你日常用这种链表，而是演示怎么从最基础的底层积木（pair），自己抽象出一套序列，为后面迭代器、Link 类打基础
