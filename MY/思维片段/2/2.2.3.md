✅ 核心提炼：抽象屏障（Abstraction Barriers）
1. 核心定义
程序分层，每层只允许调用本层约定的接口，禁止直接跨层访问底层实现；接口隔开上下层，这道隔离边界就是抽象屏障。
分层（有理数案例）从上到下：
上层业务：有理数四则运算（add_rational、mul_rational）→ 只把有理数当成完整整体
中间层：构造器 + 选择器（rational、numer、denom）→ 操作分子、分母
底层实现：基础列表 / 元组、索引取值 → 原始存储结构
规则：上层代码不能直接碰底层细节，只能调用相邻上层提供的接口。
2. 什么是【违反抽象屏障】
本该调用高层接口，却直接使用更低层级的底层操作，就是破坏屏障：
✅ 规范写法（无违规）：square_rational，复用高层 mul_rational，完全不关心内部分子分母、存储结构
⚠️ 违规 1（破一层屏障）：手动调用 numer/denom 取分子分母，直接操作内部组件
❌ 违规 2（破两层屏障）：直接写 x[0] x[1]，硬编码假设底层是双元素列表
3. 核心好处
底层存储改了（列表 → 闭包 → 元组），遵守抽象屏障的上层代码完全不用改动
代码更容易维护、重构、替换底层实现
只有构造器、选择器这一小段代码需要适配底层变更
4. 一句话总结
抽象屏障 = 分层隔离，每层只依赖对外接口，禁止直接依赖底层存储细节；遵守屏障，上层代码和底层实现解耦。
补充记忆关键点
正确性 ≠ 健壮性：三种 square 写法运行结果都正确，但只有第一种能适配后续底层修改
抽象屏障和数据抽象的关系：数据抽象是思想，抽象屏障是落地执行的规范约束
和你熟悉的 Java 对照：封装、私有成员、只通过 getter 访问，本质就是建立抽象屏障
