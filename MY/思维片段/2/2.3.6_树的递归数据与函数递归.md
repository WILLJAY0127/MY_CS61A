1. 先回忆整数拆分的核心逻辑（重中之重，这个代码完全复用这套二分选择）
问题：用不大于 m 的正整数相加凑出 n，有多少种分法？
递归二分选择：
✅ 左分支：方案里至少选一个 m
剩下还要凑：n - m，可用数字上限依然是 m
✅ 右分支：方案里完全不选 m
剩下还要凑：n，可用数字上限变成 m-1
终止条件：
n == 0 ✅ 刚好凑齐了 → 这条路是合法拆分 → 叶子标记 True
n < 0 或者 m == 0 ❌ 凑不出来 → 叶子标记 False
每一个非叶子节点的根标签就是当前正在抉择的数字 m，永远只有左右两个分支 → 所以是二叉树
2. 逐行解读 partition_tree
python
运行
def partition_tree(n, m):
    """返回一个由不超过 m 的部分组成的 n 的划分树。"""
    if n == 0:
        return tree(True)       # 成功凑完，合法路径，叶子True
    elif n < 0 or m == 0:
        return tree(False)      # 失败，这条路不行，叶子False
    else:
        left = partition_tree(n-m, m)  # 左：选m，剩余n-m，上限还是m
        right = partition_tree(n, m-1)  # 右：不选m，剩余n，上限m-1
        return tree(m, [left, right])   # 当前节点标签m，挂左右两棵子树

      /   \
  True     1
          /  \
       True   False
对应两种拆分方案：
左路径：选 2 → 2
右分支里面：选 1，再选 1 → 1+1
所以输出 [2, [True], [1, [1, [True], [False]], [False]]]
3. print_parts：遍历分拆树，打印合法方案
python
运行
def print_parts(tree, partition=[]):
    if is_leaf(tree):
        if label(tree):    # 走到True叶子，说明这条路径是有效拆分
            print(' + '.join(partition))
    else:
        left, right = branches(tree)
        m = str(label(tree))
        print_parts(left, partition + [m])  # 走左分支=选择m，把m加入拆分列表
        print_parts(right, partition)        # 走右分支=不选m，列表不变
调用 print_parts(partition_tree(6, 4))，就会输出你看到那一大串 4+2、4+1+1... 所有组合。
👉 本质：沿着树的路径收集一路上所有选中的数字，遇到 True 叶子就输出收集到的数字。

很多底层工具、算法、硬件只原生支持二叉结构（二叉搜索树、堆、表达式语法树），不支持不定数量子节点的多叉树。

于是约定一套映射规则，任何多叉树都可以翻译成二叉树存储，算法直接复用二叉树的代码。
哪怕存储形态是一条链，信息没有丢失，这就是它的理论意义。
2. 但是！这个 right_binarize 实现有短板（也是你觉得奇怪的根源）
标准孩子兄弟法是通用方案，而教材这个简化版实现，固定向右堆叠，所以极易退化成单链：
python
运行
if len(tree) > 2:
    tree = [tree[0], tree[1:]]

只要子节点多于 2 个，就一股脑打包成右侧一个节点，没有任何平衡处理。
优点：代码极简，非常适合教学演示 “多叉可以转为二叉” 这个思想
缺点：数据倾斜，退化成链表，后续查询 / 遍历的效率会变差（和链表一样 O (n)）
⚠️ 区分两件事
「多叉转二叉」这个思想很重要 ✅
「这个向右打包的简单实现」只是教学演示样例，生产几乎不用 ✖️
工程里如果要做多叉转二叉，一般会做平衡拆分，而不是无脑向右堆成一条链。
3. 什么时候能看到真正大量 “双分叉”？
只有原始节点的子节点不多于 2 个的时候。
比如输入 [1, [2,3], [4,5]]，本身每个节点最多两个孩子，转换完不会变成链，保留分叉。
但只要原始节点有 3 个及以上直接子节点，这套代码就会开始向右串成链表。
