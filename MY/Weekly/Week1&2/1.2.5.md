核心主干：Python 表达式求值规则（递归规则）
对任意函数调用表达式 func(a,b,c)，解释器固定执行 2 步：
递归求值所有子表达式：先算出 func 的值，算出 a、b、c 的值
应用（apply）：把得到的函数，作用在算出的参数上，得到最终结果
关键点：规则是递归。如果子表达式本身又是调用表达式，继续套用一模一样的两套规则。
例子：
sub(pow(2, add(1, 10)), pow(2, 5))
想要算最外层 sub，必须先算出两个参数：
参数 1：pow(2, add(1,10))
参数 2：pow(2,5)
计算pow(2, add(1,10))又需要先算add(1,10)
add(1,10)内部没有嵌套调用，抵达原始表达式（叶子节点）：数字、函数名。
两种原始表达式（递归终止条件）
数字字面量 2、5、1：值就是数字本身
名字（标识符）add、pow、sub：去 ** 环境（environment）** 查找这个名字绑定的值
重点概念 1：表达式树
求值顺序 = 自底向上
叶子节点（数字、名称）先算出值 → 值向上传递 → 上层函数使用下层结果计算。
树根 = 最外层表达式，最后才算出结果。
重点概念 2：环境 Environment（极其重要，后面闭包、函数调用全部依赖它）
原文核心结论单独拎出来：
脱离环境，单独谈论 add(x,1) 的值毫无意义。
什么是环境？
一张名字 ↔ 值 的绑定表。
add 为什么代表加法函数？因为当前环境里 add 被绑定为加法实现。
x 是什么？必须在环境里查找；环境不存在 x → 报错。
⚠️ 区分两个东西（CS61A 必考分界）
表达式 expressions：可以求值（evaluate），产出一个值
1+1、add(1,2)、pow(2,3) 全部属于表达式
语句 statements：只能执行（execute），不一定产生值，用来修改环境
x = 3 赋值语句：不返回结果，作用是在环境中新增 / 修改名字绑定
这就是文中这句话的意义：
表达式：求值，产出值；
语句：执行，产生副作用（修改环境、修改变量）。
把这段内容 和 我们之前讨论的闭包串联起来（最重要，打通你的整条知识链）
现在你先记住一条铺垫结论：
每次调用函数时，都会创建一块全新的局部环境。
python
def make_mul(factor):
    def mul(x):
        return x * factor
    return mul
m2 = make_mul(2)
make_mul(2) 调用，新建局部环境：factor → 2
返回内层函数mul
正常情况下：函数调用结束，局部环境直接销毁。
闭包特殊之处：内层函数保留对外层这块局部环境的引用！
这也就是闭包理论底层定义：
函数对象附带了它定义时所在的环境。
当你后续调用 m2(5)，mul 需要查找factor，就去这个被保留下来的旧环境寻找。
👉 CS61A 讲闭包，不会先甩语法；而是先讲「表达式求值」「环境模型」。没有弄懂环境，闭包永远是玄学。
帮你梳理容易卡住的疑问
疑问 1：递归求值顺序，是先左后右吗？
Python 规范里会依次算出所有操作数，再执行调用。
所有子表达式全部求出常量之后，才执行函数。
疑问 2：原始表达式和调用表达式分界在哪？
10：原始，叶子
add：原始（名字，查环境）
add(1,10)：调用表达式，内部还要继续求值
递归链条走到只有原始表达式，递归停止。
疑问 3：为什么要区分「求值」和「执行」？
很多新手混淆：以为所有代码都能算出值。
赋值、if、循环都是语句，目的是改变环境 / 程序流程，本身不产生返回值。
只有表达式拥有 “值”。
极简总结（方便记忆）
嵌套函数调用采用一套递归求值规则：先算所有子表达式，再调用函数；
整个计算结构可以画成表达式树，自底向上计算；
名字的值由环境决定；没有环境，符号没有含义；
代码分为两类：
表达式：求值，产生值
语句：执行，产生修改（修改环境）
环境模型是后续理解函数调用、作用域、闭包的底层基石。

环境 似乎也是抽象隔离的一种？ 以及如何区分一个节点是不是最终不可求节点，是判断一个表达式的表达数是不是真正的数字吧
第一个问题：环境是不是抽象隔离？
是的，而且这就是环境设计的核心目标之一。
先用 CS61A 的视角精准定义：
环境 = 一张「名字 → 值」绑定表。
隔离体现在这几点：
全局环境：顶层所有变量共享；
函数每次调用，新建独立局部环境
python
def f(x):
    return x + 1
f(10)
f(20)
两次调用生成两块互不干扰的局部环境。两个x完全不相干，相互隔离。
嵌套函数 → 多层环境链（父环境 + 子局部环境）
查找规则：先在当前环境找名字，找不到向上一层父环境搜寻。
这一条，直接就是闭包能够捕获变量的底层机制。
通俗总结：
环境天然提供名字空间隔离。不同层次的环境，可以存在同名变量，互不冲突。
你可以类比操作系统的进程内存隔离；环境就是编程语言层面轻量化的隔离模型。
⚠️ 一个重要区分：
环境本身只是「绑定表」；隔离是它自带能力，不是它的定义。环境最根本作用：给标识符赋予含义。原文那句核心话：脱离环境，add(x,1)毫无意义。隔离是衍生优势。
第二个问题：怎么区分叶子节点（终止节点，不需要继续拆分求值）
你的猜想不完全准确：叶子 ≠ 仅仅是数字字面量
回顾课文原文明确划分两种原始表达式（primitive expression），也就是表达式树的叶子节点：
数字字面量：2 10 5
名称（标识符）：add pow x
✅ 判断标准（通用规则）：
它不是「调用表达式」。没有 ()，不存在运算符 + 子操作数结构。
我们分两类对比：
add(1,10)
带括号，调用表达式 → 内部包含子表达式，非叶子节点，必须继续递归拆解求值
add
仅仅是名字，没有括号 → 原始表达式（叶子）
求值规则：去环境里查询这个名字绑定的值。
10
数字字面量，原始表达式（叶子）
求值规则：值就是自身。
纠正你想法里的误区
误区：叶子节点只能是数字
错误案例：表达式 pow
它是名字，叶子节点，但它不是数字，它绑定一个函数。
表达式树的内部节点 = 所有带括号的函数调用。
只要看见 xxx(...)，一定是内部节点，必须向下递归求值子表达式。
极简判定口诀（适配 CS61A 这套求值模型）
如果代码形式是 expr(a1,a2...) → 调用表达式【内部节点】，继续拆分
除此以外：数字 / 单独标识符 → 原始表达式【叶子节点，递归终止，不再向下拆分】
结合表达式例子实操一遍
sub(pow(2, add(1, 10)), pow(2, 5))
逐层识别：
sub(..., ...) → 调用表达式（内部节点）
需要先求两个参数
参数 1：pow(2, add(1,10)) → 调用表达式（内部节点）
2 叶子
add(1,10) →调用表达式（内部节点）
1 叶子
10 叶子
参数 2：pow(2,5) →调用表达式（内部节点）
2 叶子
5 叶子
所有叶子：sub、pow、2、add、1、10、5
注意！sub/pow/add 都是名字，属于叶子，去环境查表得到对应的函数。
延伸：这条模型如何衔接之前聊的闭包
函数定义时，会记录定义位置所处的环境
当函数被 return 出去，脱离外层函数调用
常规函数调用结束局部环境本可以销毁；但函数持有环境引用 → 环境被保留
这个「函数 + 绑定的父环境」整体 = 闭包
所以 CS61A 授课顺序非常讲究：
表达式求值 → 表达式树 → 原始表达式 / 调用表达式 → 环境模型 → 函数调用 → 闭包
一环扣一环，跳过环境，闭包永远只能停留在表层理解。
